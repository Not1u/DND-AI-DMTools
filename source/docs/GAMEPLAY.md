# 战斗交互与存档（0.7.0）

## 开始和继续

在 AI 面板选择模组，点“准备冒险”，后台研究与工具调用不再进入玩家对话。准备后点“开始冒险”即可收到开场，不需要自己输入启动指令。筹备阶段不会放玩家角色；进入战斗时再关联已有角色卡。

聊天自动保存。处理骰子、移动、选择、效果等状态变更后，程序自动更新当前战役快照；也可以点击“保存战役”。同一电脑重开直接读取当前状态；需要从快照恢复时点“读取上次存档”（正在战斗时不能覆盖当前状态）。

## 一次玩家回合

1. AI 发起投骰或地图请求，然后停下来等待玩家。
2. 投骰在骰盘按先后顺序进行；一次只处理队首。结果在服务器生成并保存，重试/重复点击不会重复结算。“忽略这条要求”只取消当前一条。
3. 移动：等待本角色的移动请求，拖动棋子或点击目的地，预览后点“确认提交”。系统检查当前行动者、可达路径、地形阻挡和剩余移动距离。地图采用每格 5 尺、对角 5 尺的基本格子计费，困难地形加倍。战斗外可直接自由移动。
4. 目标：按提示点击棋子，重复名字附带序号；提交的是唯一单位 ID。范围法术点击原点，橙色区域为临时预览，确认后才提交给 DM。
5. 队列处理完，AI 自动读取实际坐标、角色法术、先攻、选择结果与骰子继续。失败会显示错误，30 秒后重试，也可以手动发送消息。

紫色范围表示已经登记的持续效果。效果栏显示专注、剩余回合或剩余游戏时间。对角规则目前使用基本格子计费；机会攻击、复杂射线遮挡、特殊法术例外仍需要 DM 根据规则裁定，程序没有实现完整的 D&D 自动裁判。

## 掷骰与效果约定

以现有资料的 **2014 版 5e** 为基础，不混入 2024 版虚假生命数值。

| 场景 | 软件行为 |
|---|---|
| 玩家先攻、攻击、伤害、主动检定和豁免 | `dice.request` → 玩家点骰盘；不能在等待期间提前结算 |
| NPC 普通判定 | DM 使用 `roll.dice`，公开记录 |
| 隐藏信息的判定 | DM 使用 `dice.secret` 并写明原因，存入本地 DM 日志，不显示到玩家骰盘 |
| 被动检定 | 使用被动数值；不自动追加骰子 |
| 专注且受到伤害 | 每个伤害来源分别发起体质豁免，DC 为 10 与伤害一半向下取整中较高者；临时生命吸收伤害也会触发 |
| 专注失败、0 HP、失能或开始新专注 | 结束相应专注效果；不会无条件每回合重新投专注 |
| 临时生命 | 先扣临时值，再扣本体；不叠加，默认保留较高值；关联效果到期或耗尽后移除 |
| 持续时间 | `effect.add` 登记；回合效果在指定角色的开始/结束时点推进，战斗外用 `session.advance` 推进游戏时间，暂停软件不会按现实时间消耗法术 |

公开或暗骰属于本应用明确采用的 DM 工作约定，规则并不要求所有桌团采用唯一的掷骰公开方式。

依据：[2014 战斗规则（临时生命）](https://www.dndbeyond.com/sources/dnd/basic-rules-2014/combat)、[施法规则（专注）](https://www.dndbeyond.com/sources/dnd/basic-rules-2014/spellcasting)、[属性检定（被动检定）](https://www.dndbeyond.com/sources/dnd/basic-rules-2014/using-ability-scores)。

## 显示与法术

- AC 在棋子下方常驻显示，悬浮窗独立列出 AC、HP、先攻、豁免和来源；找不到可靠资料时显示待查证。
- 左侧角色显示当前临时 HP，角色卡内另有详情小窗。HP、地图和战斗条同步更新。
- 种族戏法放在普通戏法下方。卓尔、森林侏儒、提夫林按既有规则补齐相应能力；高等精灵须选择自己的法师戏法。种族高环法术仍显示在相应环阶，是否可施放及使用次数由 DM 核对。
- AI 使用 `scene.get` 和 `party.spells` 的完整紧凑清单识别云雾术等法术，不从被截断的装备/特性描述推断角色“没有法术”。
- NPC 台词使用 `narration.say` 显示名字与文字头像卡。没有头像图片时使用姓名缩写，不虚构图片来源。
- 滚动查看旧对话时保持原位置；“回到最新消息”恢复跟随。

## 文件位置与分享

```text
SoloTRPG.exe
runtime/                      程序
library/                      规则书、模组原件、PDF 地图缓存
saves/
  chat.json                   玩家对话（不含密钥）
  adventure.json              模组选择和后台筹备资料
  session.json                交互、持续效果、游戏时钟
  current.json                当前地图、角色副本、回合与骰子快照
  combat-log.json             本场战斗日志
  dm-rolls.json               DM 暗骰日志
  battles/*.json              战斗回放卡片完整记录
```

AI 配置和密钥、工作区设置及角色的工作副本仍在 `%APPDATA%/SoloTRPG/campaign/`。战役快照包含角色副本，聊天和战斗回放保存在 EXE 同级 `saves`；旧对话和旧战役日志会迁移过去。备份时保留 `saves` 和 `library`，另外备份 AppData 可保留个人配置。`saves` 内含后台剧透，适合主持/本地单人使用，不应当作无剧透资料发给玩家。

结束战斗会先写回放卡，再清空当前战斗日志与本场骰子结果。记录在“战斗记录 → 战役回放”查看，不需要重新执行旧战斗。

给测试者发干净 ZIP；不包含你自己的 `saves`、密钥、上传模组或地图缓存。更新时覆盖程序，保留个人 `saves` 和 `library`。

## 验证

`npm run test:desktop` 覆盖队列、并发重复点击、战斗权限、唯一目标、范围、专注、临时生命、归档及 AI 等待/续接。`npm run smoke` 验证 31 个界面面板。真实桌面测试入口 `--gameplay-smoke=<隔离测试角色模板路径>` 需同时设置 `--desktop-smoke=<隔离目录>`。

可选真实 AI 测试：`node tools/live-gameplay-smoke.mjs --live`。它会读取本机已配置的 API，发送隔离测试请求并产生服务用量；测试角色、聊天和结果均放在 build 中，退出时清除测试配置中的密钥。不要在 CI 中自动运行此项。
