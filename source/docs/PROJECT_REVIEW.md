# 项目结构与改进评估

评估日期：2026-09-11。对象：当前 SoloTRPG 独立运行目录；新仓库为 https://github.com/Not1u/DND-AI-DMTools 。

## 阅读与验证范围

已检查本项目自有的服务端、前端引擎、页面外壳、3 个扩展插件、16 个工具脚本、配置与现有说明；核对构建脚本及本地产物的关系。两个引擎文件分别为 2,502 行 / 188,124 字节和 2,492 行 / 197,531 字节。

数据文件做了全量读取、JSON/JSONL 解析和结构核查：24 个 JSON、6,803 条索引记录，无解析错误。规则书正文属于检索语料，本次没有逐条考证所有条文的准确性；第三方压缩 React 库核对用途与版本信息，exe/blob 等二进制核对产物来源，未做逆向审计。密钥仅检查存在性，不在报告中记录。

## 实际结构

```text
SoloTRPG/
├─ server.mjs                  HTTP 服务、文件服务、引擎和插件加载
├─ config.json                 监听地址、端口、数据根目录
├─ app/
│  ├─ index.html / mount.js     页面入口与 React 挂载
│  ├─ app.css / icon.ico       外壳样式、图标
│  └─ vendor/                  React / ReactDOM UMD
├─ engine/
│  ├─ ui-host.latest.txt       角色、地图、战斗、骰子、AI、索引、持久化
│  ├─ ui-client.latest.txt     React 组件、CSS、工作区布局、请求封装
│  └─ _src-phb/                本地参考 HTML；不是运行依赖，不入库
├─ plugins/                    统计、规则速查、SVG/外部图像服务
├─ rules/                      6 份结构化规则数据
├─ characters/                 4 张现有角色卡
├─ data/
│  ├─ rules-index/             39 个索引分组，6,803 条记录，约 28.9 MiB
│  ├─ maps.json / maps/        地图目录及各地图文件
│  ├─ map.json                 当前地图的兼容镜像
│  ├─ combat-state.json        先攻、回合、行动经济
│  ├─ combat-log.json          战斗事件记录
│  ├─ dice.json                投骰请求和结果
│  ├─ workspace.json           面板布局
│  ├─ theme.json               主题
│  ├─ ai.json                  本地密钥、AI 设置及对话；不入库
│  └─ images/                  已导出的地图 SVG
├─ tools/                      构建、索引、迁移、探针、测试及旧适配器工具
├─ docs/                       当前架构评估、开发工作流
├─ build/ / dist/ / *.exe      本机构建产物，不入库
└─ HANDOVER.md / README.md.repo 历史交接资料，不能当作当前结构说明
```

实际调用链为：浏览器 → `POST /api`（别名 `/dnd5e/api`）→ 核心 op 或插件 → JSON 文件。AI 的工具调用最终也进入这套 op。`engine/*.txt` 是可执行 JavaScript 函数体，通过 `new Function` 注入依赖，并非普通文本资料。

本目录没有旧文档中的 `core/`、`adapters/`、`schema/` 和 `standalone/`。它是从旧工程复制出来的独立版，不能套用旧工程的“三层已拆分”描述。

## 结构是否合理

**方向合理，工程边界尚未落实。适合继续作为本地单用户应用演进，暂不适合直接开放为多人网络服务。**

优点：UI、AI 和脚本共用业务入口；规则数据与执行代码基本分离；插件扩展成本低；本地 JSON 易查看和备份；运行依赖轻，支持离线界面；已有渲染冒烟检查。保留这几个方向即可，不需要为了重构引入微服务。

主要代价：两个大文件承载几乎全部职责；界面样式与组件混放；业务规则在前后端及导出插件中重复；JSON 文件间状态同步依赖调用者；参数格式混用对象和 `{json: "..."}`；热加载与缓存使错误定位和测试隔离更难。当前的模块化更多体现在目录名和接口名，而不是可独立测试的代码模块。

## 优先修复的问题

以下是初始版本中的问题；本轮保留业务代码作为基线，没有顺手修复它们。

| 优先级 | 位置 / 触发 | 发现与影响 | 建议 |
|---|---|---|---|
| P0 | `server.mjs` 的 `/files/` | 可以读取整个 ROOT 下的文件，包含 `data/ai.json` 和新增的 `.git`；`safeJoin` 仅比较字符串前缀，目录边界也不严谨 | 文件服务改为仅允许导出资源；用 `path.relative` 校验边界，考虑符号链接；限制 Host/Origin 和监听范围 |
| P1 | client：`StatusPanel`、`EquipPanel`、`Bag` | 局部 `const call` 内再次调用 `call`，实际递归自身，未进入公共传输层 | 将局部操作函数改名并加入按钮点击回归 |
| P1 | client：`SettingsPanel.save` | 未接收 `opts` 却读取 `opts.silent`；请求保存后抛错，“保存并测试”无法正常继续 | 明确参数及 finally 状态复位，测试保存与连接两条路径 |
| P1 | host：`levelset.info/apply` | 总等级与主职业等级混用；内存复现总等级 5→6 后职业和变成 7 | 使用目标职业及职业等级增量，统一派生总等级；补齐升级选择校验 |
| P1 | host：`combat.next` | 战斗状态跨轮更新，但 `pushLog` 未传新 round；复现战斗 R2、日志仍 R1 | 统一轮次来源，生成事件时记录同一 round |
| P1 | host：`persist/readPc/pc.apply`、`writeMap` | 原地修改缓存、直接覆盖文件；`pc.apply` 绕过 `readPc` 的失效检查；多文件写入有的结果被忽略 | 引入存储层、原子替换、串行写入与版本号；失败不能报告完整成功 |
| P1 | host：`combat.damage` 等 | 角色、地图、先攻各自按原值加减；其他写入口不会同步这三份，已有偏差会一直保留 | 以实体 ID 关联，确立 HP/状态唯一来源，统一伤害与临时 HP 结算 |
| P1 | host：AI 派发 | 工具 schema 主要发给模型，没有统一的服务端参数验证；派发未强制限制到本轮工具白名单；工具可直接修改存档 | 注册时集中定义 schema、读写属性和 handler；调用前校验与记录；添加操作撤销或检查点 |
| P2 | host `roll.dice` / client `DicePanel` | `append:false` 返回 total/detail，却不返回 dice/dropped，动画拿不到骰面；“忽略这条要求”调用 clear all，会清掉全部请求和结果 | 统一骰子响应契约，增加单条取消操作 |
| P2 | client `mcPrereqInfo` | 用属性修正判断 ≥13，无法区分 12 和 13；显示值也从修正错误反推 | 角色视图返回原始属性值；前后端使用同一前置条件数据 |
| P2 | host 地图 / image-export 插件 | UI 定义 21 类瓦片，mapView 图例和 SVG 插件仍保留 12 类；部分样式回退为普通地面 | 统一瓦片目录及导出映射 |
| P2 | `plugins/encounter-stats.mjs` | 伤害统计依赖 detail 末尾 `= 数字`，而 `combat.damage` 输出另一种格式；“未命中”也含“命中” | 统计结构化事件字段，不解析自然语言 |
| P2 | host `map.los` | 当前 cover 累加分支限制 `<2`，无法按注释升到四分之三掩体；相邻墙直接跳过 | 将实现与选定规则/房规定义对齐，加入几何边界用例 |

其他技术债：`writeMap` 的 return 后有不可达旧代码；删除插件后的缓存列表可能残留；前后端默认布局不一致；AI 对话与设置共存于同一文件，长请求结束可能覆盖期间的新设置；AI 请求缺少超时/取消及失败后的完整工具记录；工具输出直接截断 JSON，易损失字段。规则版本、房规和法术模板也需明确区分并单独核验。

## 测试与工具现状

- `node tools/smoke-ui.mjs`：通过。共 31 次组件/页签渲染检查，包含工作区深度遍历及若干纯函数断言；**没有验证真实浏览器点击流程**。
- `node tools/check-ui.mjs`：通过组件引用检查。常量扫描有词语误报，不能替代作用域分析或 lint。
- 23 个 `.js/.mjs` 语法检查，加两个引擎函数体编译：共 25 项通过。
- 注入本目录 ROOT、把全部写操作转向内存后，角色卡 4 张可读，12 职业建卡选项可读，规则检索可用；注册 76 个核心 op，手工目录 61 条，默认 AI 工具 40 个。插件另有 6 个 op。
- 数据中有 361 条法术；模组分组 624 条记录、37 个模组名称；不代表拥有 37 本模组的完整冒险正文。
- 多职业升级和跨轮日志缺陷已通过内存运行复现，原存档没有变更。
- `test-host.mjs`、`test-equip.mjs` 没有注入 ROOT，仍可能读旧工程；前者报告失败也未设置失败退出码。
- `preflight-host/client` 与 `build-adapter` 面向缺失的旧 `adapters/`；`find-rules` 引用缺失的 `core/rules-finder.mjs`。
- `dnd-api`、地图生成器默认连接旧端口 43120；独立服务默认是 4620，使用时需设置 `DND5E_API`。
- `health.mjs` 会修改现有角色状态并导出 SVG，不是只读检查，且恢复方式会误删原有同名状态，本轮没有对真实存档运行。
- 尚未做真实模型调用、完整浏览器端到端验收或 exe 重构建；不得将本次结果表述为所有功能已验收。

## 建议的演进顺序

1. **修复可复现缺陷。** 优先文件访问边界、按钮递归、设置保存、等级与轮次；把本次复现变成不会触碰存档的回归用例。
2. **抽出存储与接口契约。** 新建 `src/storage/` 和 `src/api/`，统一错误返回、schema 校验、写入顺序、备份与撤销；保留现有 op 名便于渐进迁移。
3. **按领域拆分引擎。** 后端分为 characters、combat、maps、dice、rules、ai；前端把组件、hooks、CSS、传输层拆开；共享瓦片、状态与职业规则数据。
4. **建立可靠测试入口。** `npm test` 统一运行语法、业务规则与集成测试；浏览器测试覆盖建卡、装备、设置、发起投骰、战斗跨轮、升级。CI 只运行隔离测试。
5. **改善产品体验。** 状态更新用统一订阅替代各面板重复轮询；AI 支持流式输出、暂停/取消、多会话和上下文裁剪；补齐资源消耗及恢复。
6. **收敛构建与数据分发。** 构建依赖固定版本并提交锁文件；源码、示例、个人存档分层；版本发布用 GitHub Releases 附完整便携包。现有 build/ 内锁文件被忽略，构建脚本会按当时版本安装依赖，尚不完全可复现。

建议目标结构是 `src/server/`、`src/domain/`、`src/storage/`、`src/ai/`、`src/shared/`、`app/components/`、`app/hooks/`、`app/styles/`、`tests/`。分阶段迁移，先建立行为测试，再拆文件，避免一次重写导致规则行为变化。
