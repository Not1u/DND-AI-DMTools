# 0.12.0 主界面、人工 DM 与用量控制

启动进入主界面。原有数据作为“原有战役”保留；新建流程选择/导入模组、选择是否启用 AI DM，再进入角色创建。存档可选择玩家工作区或 DM 控制台。

新存档的小型角色与配置文件位于原 AppData campaign/profiles/<id>；对话、当前状态快照、战役记录位于程序旁 saves/slots/<id>。模组与 PDF 图片共用 library，不重复复制。切换会保存当前快照；处理中的 API/AI 请求结束前拒绝切换，避免写入错误存档。新建存档复制现有 AI 配置但不复制对话。

人工 DM 模式关闭 ai.chat 的普通主持请求和 session.resume 自动续接。玩家输入记录为玩家行动，等待人工回复。控制台把工具 schema 渲染为表单，提供骰子、生命值、效果、回合、敌人绑定、地图操作、发言、记录等快捷入口；复杂自由结构参数保留高级 JSON 输入。每次执行显示成功/失败与回执。

按需 AI 规则/判断工具为只读；地图助手可在非战斗状态生成地图；记录助手先给文本预览，DM 确认后写入日志。地图移动与战斗的真实日志继续本地生成，无需为每次移动付模型费用。辅助回复不混入玩家的 DM 剧情对话。

## Token 控制

默认节省模式最多3轮模型请求，每轮最多1200输出 token；均衡最多5轮/2400。模组自动上下文从最多20000字符减为1200，历史只携带最近10条并限制总量7000字符；大地图格子、范围格集合和冗长装备说明不再反复自动注入。需要细节仍可通过规则或地图工具查询。

单次请求序列化体受字符预算限制（节省48000、均衡80000）；服务商累计报告达到16000/30000 token 后停止下一轮。该阈值是续调预算，首个响应可越过阈值，不是精确账单上限。未返回 usage 的服务商无法准确统计，但仍受轮数、请求体和输出上限约束。控制台展示服务商报告的输入、输出与请求字符数，不将未知用量伪装成零。

上下文缩短可能需要更多有针对性的查阅；长期完整对话仍留在存档中，不被删除。没有声称对所有模型都能固定减少某个百分比。

联机仅规划，见 P2P_PLAN.md。

AI 续接失败后停止自动重试，需要人工再次发起，避免无限后台消耗；接口兼容性重试同样计入轮数上限。
