# 0.13.0 局域网手机测试版

## 最短验证路径

1. 电脑打开最外层 SoloTRPG.exe，在主界面选一个测试存档，以 DM 进入。新战役先完成导入模组、新建角色；在地图中放入这个角色。
2. 进入 DM 控制台，关闭“启用 AI DM 自动主持”。在“手机 / 局域网联机”中开启房间。
3. 选择角色，点“生成玩家邀请”。连接地址选择电脑 Wi-Fi 或以太网的 IPv4 地址（手机不能用 127.0.0.1）。复制完整邀请链接到手机浏览器打开。
4. 两台设备连接同一局域网；电脑走网线、手机连同一路由器的 Wi-Fi 也可以。Windows 若询问网络访问，在可信的专用网络允许 SoloTRPG/runtime 程序通过。不要关闭整个防火墙。访客 Wi-Fi 的设备隔离、VPN/虚拟网卡或错误 IP 都可能使连接失败。可先在电脑浏览器使用 127.0.0.1 邀请链接验证页面。
5. DM 确认地形可以展示后，点“公开当前整张示意图”。手机看到地形及当时未隐藏的棋子。地图笔记、模组正文、暗骰、电脑私有对话和 API 密钥不发送给手机。

## 建议按顺序测试

| 操作 | 手机上的预期 | 电脑上的预期 |
|---|---|---|
| 自由探索时点空格，再点提交移动 | 出现“移动已生效”回执 | 地图坐标更新 |
| 输入“向守卫问路”，提交 | 等待 DM | 房间列表出现请求，点接收意图 |
| DM 在“发给所有手机玩家”发言 | 约 2 秒内看到公开回复 | 同时进入桌面 DM 对话 |
| DM 用骰子接口指定该角色、表达式与检定名称 | 出现投骰按钮，点后显示结果 | 现有投骰队列完成，结果一致 |
| DM 建立先攻，轮到玩家后移动 | 等待批准，未批准前不移动 | 批准后执行距离及回合校验 |
| 手机结束我的回合 | 等待 DM，批准后显示下一回合 | 推进一次；重复批准不重复推进 |
| 手机刷新页面或暂时切走再回来 | 自动恢复同一个角色的视图 | 不生成新角色或重掷骰子 |
| DM 撤销邀请 / 关闭房间 | 提示邀请失效 / 连接中断 | 旧邀请不能继续操作 |

## 本版范围

- 移动、投骰和回合推进使用电脑现有规则执行器。未知或失效操作返回“未执行”，不能按成功继续。
- 法术选择＋地图目标＋自定义文本是**行动意图**。人工 DM 接收后，仍需使用现有可视化接口进行规则裁定、命中/伤害请求、资源和状态更新；首版没有把全部法术范围与自动结算搬到手机。
- 法术位余额使用已有战斗资源记录；尚未确认的余额显示“待确认”，不能当满槽。
- 地形由 DM 显式发布快照；已发布棋子的位置和自己的 HP/AC 随权威状态刷新。新地图/新棋子需重新公开。隐藏棋子不发送。公开整张地形意味着没有逐格战争迷雾保护；请用可公开的局部示意图。PDF 原图不传输。
- 手机对话只显示房间公开发言和公开行动回执，不读取整段私有战役历史。可继续用 AI 地图、规则和记录辅助，但要由 DM 选择公开哪些内容。
- 最多五个已分配角色，每个角色一个邀请；邀请 24 小时有效，可撤销。房间、邀请和审批队列只保存在进程内存，关闭/重开房间后失效。已实际执行的操作仍使用现有战役持久化。
- 手机暂用适配浏览器页面，无需 APK/iOS 安装包。采用局域网 HTTP、2 秒轮询，不是 WebRTC P2P、公网房间或加密隧道；仅用于可信局域网，不做端口映射公开到互联网。
- 主机关闭后暂停连接；再次开启房间会生成新端口和邀请。房间开着时不能切换存档或启用 AI 自动主持。

## 实现与后续

独立网关 src/lan.mjs 只提供静态手机页面、GET /state 和 POST /intent。电脑本地服务继续监听 127.0.0.1；开启房间后才增加玩家专用监听。远端没有通用 op 或文件接口。服务端绑定角色、限制请求体/速率、过滤视图；幂等请求在当前房间内防止网络重试重复执行。DM 批准前再次检查场景版本及回合。

下一阶段可在保持 intent/回执和角色授权模型的基础上接入 WebRTC 信令、STUN/TURN、可靠事件序号和重连补偿；见 P2P_PLAN.md。原生手机壳应在这次实机验证后决定，当前没有原生安装包。

## 验证记录

隔离 HTTP 双端测试覆盖权限边界、隐藏信息过滤、越权 actorId、回合限制、DM 审批、重复投骰、撤销邀请、私有/公开对话及旧请求拒绝。桌面 --lan-smoke 用实际按钮事件启动房间、分配角色，并在 430px 独立浏览器窗口验证地图点击、审批、回复、投骰、结束回合和刷新重连。实体手机与具体家庭路由器的连通性需用户实测，不能由窗口模拟替代。
